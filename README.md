# growi-plugin-calendarv2

GROWI に「イベントカレンダー(閲覧専用)」と「出欠(空き日程)入力カレンダー」の2つを追加する
script プラグイン。旧 `growi-plugin-calendar` の作り直し版(ディレクティブではなく
**コードフェンス言語**をフックする方式）。

## 記法

remark-directive ではなく、**Markdown のコードフェンス(```)の言語名**をフックして
実際の React コンポーネントに差し替える方式を採る。中身は空でよい。

### イベント一覧カレンダー(閲覧専用)

````
```growi-calendar
```
````

月送りできるカレンダーグリッドを表示し、固定ページ
**`/イベント/決定済みイベント保管場所`** の本文をパースしてイベントを月別に表示する。

イベントページの記法(パース対象の行):

```
8月20日 部会
16時30分〜Zoomで説明会
8時〜9時　同志社国際
```

- `M月D日` の後にタイトル。時刻はあってもなくてもよい
- 時刻は `H:MM` または日本語の `H時(M分)` 形式、区切り文字は `〜` `～` `~` `-` のどれでもよい
- 年をまたぐ判定は「月番号が前の行より小さくなったら年を+1」という単純な推測（**手動で
  年を書く欄は無い**ため、年をまたぐイベント一覧を書く順序を崩すと年がズレる）

### 出欠(空き日程)入力カレンダー

````
```growi-availability
```
````

ログインユーザー自身の月間の出欠(○/△/×)を入力するカレンダー。保存先は
ページパス **`/schedule/responses/<year>-<month>/<username>`**（ユーザーごとに専用ページを
持つ）。本文は次の固定フォーマットで書き戻される（他の内容と混在させない）:

```
​```growi-availability
​```
<!-- availability
{"2026-09-20":"yes","2026-09-21":"maybe"}
-->
```

操作方法:

- セルをクリック: `未設定 → ○(yes) → △(maybe) → ×(no) → 未設定` の順に循環
- セルをドラッグ: 最初に触れたセルで決まった値を、なぞった範囲全部に一括で塗る
  （API 呼び出しはドラッグ終了時に1回だけ）
- 「全部○/△/×にする」ボタン: 当月全体を一括設定
- 「前月からコピー」ボタン: 前月の入力を日付をそのままスライドして今月にコピー
  （前月にあって今月に存在しない日付＝31日等はスキップ）

### 出欠の集計・投票状況ビュー

`CalendarSummary`（`growi-calendar` 側）は `/schedule/responses/<yearMonth>/` 配下の
全ユーザーのページを読み集計し、日付ごとに ○/△/× を投じた人数を出す。スコアは
（おそらく ○=+1 / △=0 / ×=-1 的な合計）を緑(プラス)〜黄(0)〜赤(マイナス)の
グラデーションで表示し、日付をタップするとその日の詳細な内訳を見られる。

## 仕組み

- `client-entry.tsx` 一本構成（`src/` ディレクトリなし）。`growiFacade.markdownRenderer`
  の `options.components.code` をラップし、`className` に `growi-calendar` /
  `growi-availability` を含むコードブロックだけ差し替える。他の言語のコードブロックは
  元のハンドラにそのままフォールバックする。
- イベント一覧・出欠データは **GROWI ページ本文をそのまま DB 代わりに使う**設計。
  専用の保存 API・DB テーブルは持たない。
  - イベント一覧: 固定パス `/イベント/決定済みイベント保管場所` を `/_api/v3/pages/list`
    → `/_api/v3/page` で取得しテキストパース
  - 出欠: `/schedule/responses/<yearMonth>/<username>` ページの本文中 HTML コメント
    `<!-- availability {...} -->` に JSON を埋め込み、`/_api/v3/page` の更新 API で保存
- ユーザー名は `/_api/v3/personal-setting` から取得（`growiFacade` 自体にはユーザー情報が無い）。

## セットアップ

```bash
pnpm install
pnpm build     # dist/ に成果物を生成
```

GROWI はプラグインを GitHub リポジトリから直接取得し、`dist/manifest.json` を読むだけで
サーバー側ビルドは行わない。**`dist/` はビルド後に必ず commit して push すること。**

1. このリポジトリを GitHub に push
2. GROWI 管理画面 → プラグイン → 「プラグインインストーラー」に GitHub URL を入力
3. `/イベント/決定済みイベント保管場所` ページを作成し、上記フォーマットでイベントを書く
   （イベントカレンダーを使う場合）
4. 好きなページに `growi-calendar` / `growi-availability` コードフェンスを置く

## 既知の制約・注意点

- **イベント一覧の参照先ページパスがコード直書き**（`/イベント/決定済みイベント保管場所`）。
  Wiki 側でこのページ名・パスを変更すると、コードも直して再ビルドしない限りカレンダーは
  空になる。
- **出欠データはページ本文の HTML コメントに JSON を埋め込む方式**であり、専用 DB を
  持たない。ユーザーがそのページの本文を手動編集すると壊れる可能性がある（コメント部分の
  JSON パースに失敗すると、そのユーザーの出欠は集計から静かに除外される）。
- 年またぎの判定はイベント一覧の**行の並び順に依存**する単純な推測ロジック。イベントを
  月順に並べずに書くと年がズレる。
- 出欠の入力・保存は「月全体をまとめて1回 API に書く」設計（1マスずつは呼ばない）ため、
  同じユーザーが複数タブ/デバイスで同時編集すると後勝ちで上書きされる（楽観ロックなし）。
- `pnpm-workspace.yaml` に既知の重複ファイル `client-entry.js`（ビルド前の中間生成物?）が
  残っている場合がある。ビルド成果物として意味を持つのは `client-entry.tsx` から
  `pnpm build` で生成される `dist/` のみ。
